# Engine code map

Keep this file current: every change that adds, moves, splits or re-purposes a file updates its line.

Read this first to find code; grep only inside the files it points to. Paths are relative to the repository root.
Line format: `path` - what it owns. **K:** key types / functions. **M:** manifest keys or schema it handles.
A change describes itself in plain words (no package or milestone codes). Files still being written are marked *(in progress)*.

## Layout at a glance

| Folder | What |
| --- | --- |
| `include/capsule/<area>/` | public headers, one folder per area (namespace `capsule::<area>`) |
| `src/<area>/` | implementations; `*_empty.cpp` / `*_default.cpp` are link-time defaults a game replaces |
| `tools/` | Python compilers (manifest JSON -> C++ tables); `tools/battlec/` = battle compiler sections |
| `cmake/parts/` | CMake parts per feature (sources, generated data, tests) |
| `tests/` | C++ test programs (`*_tests.cpp`), Python tests (`test_*.py`), `tests/data/` inputs and goldens |
| `apps/<app>/` | games-shaped apps: `reference/project.json` (capsule.project/1), `data/`, `src/` |
| `assets/` | engine default font, input map, ASCII code page |
| `docs/` | topic docs split from the README: `BUILDING.md`, `ARCHITECTURE.md`, `DATA_FORMATS.md`, `BATTLE.md`, `SCRIPTS.md`, `AUDIO.md`, `APPS.md`, `TOOLS_AND_CI.md`, `CONTRIBUTING.md`, this `CODE_MAP.md`; `README.md` keeps the index (old section names -> topic file), licence and credits; `CHANGELOG.md` per release |
| `samples/` | sample games new users copy (`samples/starter`: the Starter sample, the engine's neutral reference fixture); `samples/starter/README.md`: the Starter rules table, every number and formula, the Starter's rules; stage-two species by level, Sproutle's Bloom Charm, Glimmet's Radiant form, training (samples/starter/README.md rows Transformations, Forms, Training); F1: the Ward charm's timed field effect `ward` (120 steps), the global `ward_rule` and Quick Feet's `on encounter` (x3/2) in `effects/field.ceffect` / `passives.ceffect` (README row Field rules) | the field actions: the field actions wade / clear / light in `structure.json` `field_actions` (README row Field actions) | the step effects: the step effects blight (every 4 steps, survive rule, message blight_survived) / bond (every 64) in `structure.json` `step_effects`, the custom role bond, Blight's `on steps` (effects/conditions.ceffect) and the global bond_rule (effects/field.ceffect) (README row Step effects) | the combination: the Merge Altar `merge_altar` in `structure.json` `combine_methods` (a type table, consumed), species `combine_moves`, the global merge_rule (effects/field.ceffect) (README row Combination)

- `include/capsule/core/random.h` - RNG streams (A-4). **K:** rng::Stream, next16(), below(), between(), chance(), mix(), seed(); FrameCondition, set_frame_advance(), frame_advance() (one gameplay draw per frame while the game's condition holds; each HAL's system::update() calls it after the frame's vertical blank), frame_advances(); AdvanceClock (Blank: every hardware blank draws, the default; Frame: one draw per update()), set_advance_clock() / advance_clock(); spend_blanks() / spent_blanks() (a game frame that also spends N hardware blanks: N more per-frame advances, the counts being the game's data)

## Build and test entry points

- Configure + build (headless): `cmake -S . -B <build> -DCAPSULE_PLATFORM=headless -DCMAKE_BUILD_TYPE=Debug; cmake --build <build> -j2`

  sequence_compiler_tests, asset_tests, asset_compiler_tests, bitmap_tests, map_tests, map_compiler_tests,

- Style: `python3 tools/ci/check_style.py <files>`; principles: `bash tools/ci/check_principles.sh`
- Golden re-record (only after an intended change; say why in the package report):
  - the first content (classic) goldens: in the reference-ruleset repo (`classic_golden_tests`)
  - Starter goldens: `CAPSULE_GOLDEN_RECORD=1 ctest -R starter_golden_tests` (the bench scenarios in tests/bench/starter must still pass)

  - transfer golden: `python3 tests/test_record_transfer.py --record`
- Snapshot: a changed generated output fails generated_snapshot_tests. If intended: add the outputs and the reason to
  RECORDED_CHANGES in `tests/test_generated_snapshot.py`, then `python3 tests/test_generated_snapshot.py --record`.
  Depfiles are not compared. Never record to silence an unexplained change.
